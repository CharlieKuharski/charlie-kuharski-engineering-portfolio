# Owner checklist before publication

This folder is prepared locally. Nothing has been uploaded, no remote has been created, and no Git history from the source projects is included.

- [ ] Review every included file and both images; confirm this is the disclosure you want.
- [ ] Have an IP attorney review the draft evaluation terms and confirm ownership/authority for the materials being shared. Finalize the root license before uploading.
- [ ] Keep the OVA queue sample's MIT license and third-party notices. Do not describe that sample as restricted to hiring evaluation.
- [ ] Resolve existing distribution scope: OVA's source tree has an MIT license, and the deployment repository's notice refers to Apache-2.0 licensing for deployment materials and the OM container distribution. This package does not determine what rights were already granted or revoke them.
- [ ] Remember that a public GitHub repository can be viewed and forked under GitHub's platform terms. A restrictive notice does not technically prevent copying or create confidentiality.
- [ ] Check career statements and source-provenance records. Keep the persistence case study labeled as locally tested until deployment verification is actually complete.
- [ ] Run the sample commands on a clean machine or fresh checkout. Review [verification](verification.md) for the preparation-time results and limits.
- [ ] Upload only this folder's contents to the intended new repository. Do not add private source trees, databases, screenshots from live projects, `.env` files, or the original `.git` directories.

No publication command is run by the preparation scripts. A demo video link is intentionally omitted until a video exists.
